# PrimebotX 前后端接口草案 v0.2

> 历史接口规划：本轮以《文档2_独立需求分析》为需求、《文档3_最小后端与后续工作》为已实现接口清单。下列路径不代表已实现。

本文件是 MVP 联调协议。接口由我们自己提供，不是 Q1 官方 HTTP 接口。第一版同源部署、单机器人、单控制会话。

## 1. 通用返回结构

~~~json
{"request_id":"req-001","data":{},"error":null}
~~~

HTTP：400 参数错误，404 不存在，409 控制冲突或忙碌，422 当前能力不支持，503 机器人通信不可用，504 等待响应超时。写操作必须带 Idempotency-Key，超时不能由前端自动重试。

## 2. MVP 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | /api/v1/health | 后端健康，不代表机器人在线 |
| GET | /api/v1/robots | 查询 Q1 设备档案 |
| POST | /api/v1/connections | { robot_id, mode: mock 或 ros2 } |
| GET | /api/v1/connection | disconnected/checking/ready/degraded/error |
| DELETE | /api/v1/connection | 断开会话并尝试停止移动 |
| GET | /api/v1/status | 电量、连接状态、运动状态、数据时间 |
| GET | /api/v1/capabilities | 后端白名单动作、表情、相机 |
| POST | /api/v1/tts | { text, interrupt } |
| GET/PUT | /api/v1/audio | 获取或设置音量、静音 |
| POST | /api/v1/actions | { action_id } |
| POST | /api/v1/emotions | { emotion_id } |
| POST | /api/v1/control/lease | 申请唯一移动控制会话 |
| POST | /api/v1/motion/target | 持续发送速度目标；左右未确定前只开放前后 |
| POST | /api/v1/motion/stop | 清除目标并尝试零速度 |
| GET | /api/v1/logs?after_id=&limit=100 | 增量读取本系统日志 |
| GET | /api/v1/cameras | 查询配置的相机 ID |
| GET | /api/v1/cameras/{id}/snapshot | 获取 JPEG 单帧 |

## 3. 数据约定

电量使用 Bms.remaining_capacity_percentage；无观测时为 null。信号强度没有确认的 SDK 接口，返回 null。后端把 q1.wave 映射到 Q_WAVE_HAND=3004 等 SDK 常量；前端不直接传任意整数。Dialog、Tendance 只是展示分类。

移动请求示例：

~~~json
{"control_token":"lease-001","seq":1,"forward_velocity_mps":0.2,"lateral_velocity_mps":0.0,"angular_velocity_radps":0.0}
~~~

在左右含义确认、真机安全验证完成前，后端拒绝非零侧移和旋转速度。前端必须处理 pointerup、pointercancel、页面失焦；普通 stop 不等同于物理急停。

## 4. 前端接入规则

- 新增 js/api.js，所有请求通过它，页面业务代码不拼 ROS 服务名。
- Connect 先显示 checking，业务接口探测成功才显示 ready。
- HUD 更新电量后调用现有 window.hudBatt()；模拟模式显示 MOCK。
- 快捷动作卡片绑定 data-action-id，按 capabilities 动态渲染；未核实动作禁用。
- Chat 与 TTS 分离。聊天接口以后单独增加，播报调用 /tts。
- Log 只展示本系统日志；机器人板卡日志另行导出。

## 5. 联调顺序

1. mock：连接、状态、电量、能力、播报、动作、日志。
2. 前端错误状态：未连接、能力禁用、重复点击、超时、模拟标记。
3. Ubuntu 真机只读：节点、服务、电量。
4. 真机音频和表情，再验证预设动作。
5. 确认左右键后才开放移动；相机先截图，RTSP 视频另行评审。
